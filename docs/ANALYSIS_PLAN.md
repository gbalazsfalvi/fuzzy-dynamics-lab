# Frozen evaluation analysis plan

**Date:** 17 November 2026. **Version:** analysis-v1.  
**Status at authoring:** specified before final test outputs exist or have been inspected by the analysis implementer. This plan specializes the broader proposed `EXPERIMENT_PROTOCOL.md`; deviations from that proposal are explicit below.

**Goal:** analyze saved frozen evaluation evidence without rerunning, retraining, selecting, or tuning methods.  
**Architecture:** a read-only artifact loader validates the paired cohort and provenance; pure grouped estimators feed machine-readable summaries, a report, and standalone figures. Input evidence is never overwritten.  
**Stack:** Python standard library, NumPy, and Matplotlib from the locked `learning/.venv` environment. No learning modules are imported.  
**Scope:** `analysis/**` and this document only. The implementing parent owns the final freeze and execution. No further delegation or publication occurs in this analysis task.

## Frozen inputs and eligibility

The default input is `artifacts/evaluation`, the default freeze is `research/evaluation-freeze-v1.json`, and the default output is `artifacts/evaluation-analysis`. All paths are CLI-overridable. Required saved files are `manifest.json`, `outcomes.csv`, `measurements.csv`, `alpha-diagnostics.csv`, `reference-errors.csv`, `refinement-curves.csv`, and the manifest's individually hashed numerical evidence files. The CLI validates schema, unique full problem-method-tolerance coverage, timing counts and consistency, safe payload paths, and hashes. It does not reproduce Java numerical proofs: the separate Java replay remains required.

Before the final freeze, storage was extended to accept `runs/<safe-id>.json.gz` as well as plain `.json`. The digest covers actual stored file bytes. After digest verification, the reader decodes each payload separately with a 64 MiB decoded-size limit and parses its JSON object, without retaining full-cohort geometry. This is a storage-only change; it alters no estimator, cohort, endpoint, or statistical decision rule.

The freeze supplies `primaryDeterministicMethod`, `primaryLearnedFamily`, `primaryLearningMethodIds`, `protocolSha256`, and `sourceSha256`. The deterministic comparator is selected on validation by most certified outcomes, then lowest median algorithm map-image count, then alphabetical method ID. The learned family is selected on validation by success rate, then median map-image count. All five MLP model seeds (11, 23, 37, 51, 71) remain represented if MLP is selected; no best-seed choice is permitted. Ridge has a single deterministic fit, so its analysis cannot estimate training-seed uncertainty. All declared methods and all seeds are retained in descriptive tables regardless of the selected primary family.

The final cohort has four regimes identified by `test-id-1d-`, `test-id-2d-`, `test-ood-1d-`, and `test-ood-2d-`, with at least 30 distinct base problems per regime. `baseProblemId` in the embedded protocol is the grouping authority. All horizon/tolerance variants of a base remain together. The targeted configuration uses tolerance 0.1, precision 24, at most 512 completed splits, and ID horizons 2/4 and OOD horizons 6/8. A preselected timing cohort contains 12 base problems: indices 000, 010, and 020 in each regime. Its `Problem.timingCohort` flag is authoritative. Only these receive one warmup and five timed repetitions and enter runtime ratios, verification-overhead timing summaries, and completion curves. The other 108 receive one numerical observation without warmup; their recorded durations are retained as raw evidence but excluded from timing conclusions. All 120 enter success and algorithm-work analyses. This stratified timing design was selected before final outcomes to bound computational cost, not selected for observed success. The final embedded protocol and freeze determine the actual declared cohort and budgets. An unknown regime or cross-regime reuse of a base ID is rejected.

All 32 declared methods remain represented: four deterministic CAE policies, ridge, five MLP seeds, 20 random-priority policies `random-seed-0` through `random-seed-19`, alpha grid, and published PWL core. Random-priority methods share the certificate and fairness engine; they are descriptive stochastic controls and are not candidates for the validation-selected deterministic comparator. No stochastic seed is removed or selected by final performance.

## Endpoints and weighting

The primary endpoint is the learned-family minus selected-deterministic certification-rate difference, averaged equally across the four regimes. Within a regime every base problem has equal weight, each of its variants has equal weight, and every retained learned model seed has equal weight. `CERTIFIED` is success; budget exits, cancellation, numerical failures, and unavailable primary requests are non-success. Primary unavailable rows are explicitly counted rather than silently removed. A positive difference favors the learned family. This certification endpoint replaces the broader proposed protocol's primary time endpoint because finite budgets and incomplete certification make an unconditional successful-subset runtime claim misleading.

Per-regime certification differences and the full method/regime outcome table are secondary descriptive results. The table includes requested rows, eligible rows, distinct base problems, certified rows, budget exits, all other failure statuses, unavailable rows, and both requested and eligible success fractions. It preserves individual seed method IDs.

The secondary paired runtime ratio is learned/deterministic on the 12 preselected timing bases, using the median total in-process duration of each run's five timed repetitions. It is defined only when both runs are certified and both median durations are strictly positive. Within each base/seed pair, multiple eligible variant ratios are combined by geometric mean. The reported statistic is the median of those base/seed ratios. Its confidence interval uses the same base/seed resampling as below, restricted to the declared timing bases, never selecting bases by success. Every report includes the both-certified denominator, timing-cohort base count, and number of excluded pairs. This ratio is explicitly conditional; it is never called an unconditional speedup, a time-to-solution estimate for failures, or evidence of dominance of the full cohort. Map-image ratios use all 120 bases, the same both-certified pair eligibility and positive-work requirement, and are descriptive. Raw map-image and exact-point counters remain separate for differing representations.

## Grouped uncertainty

Use 10,000 percentile bootstrap replicates and seed 20261117. Each replicate resamples whole base-problem IDs with replacement **within each regime**, keeping all variant rows together. For a selected learned family with multiple models, sample the model-seed axis with replacement once per replicate and use that same seed sample for every selected base and every regime. This crossed cluster resampling reflects models shared across problems; drawing a fresh seed independently for each problem would erase shared model uncertainty. Do not resample cells, trajectory times, refinement rows, or timing repetitions as scientific instances.

Report the 2.5 and 97.5 percentiles, the number of valid replicates, and the original base/model counts. A conditional statistic with no qualifying pair is unavailable, not zero; bootstrap replicates without a qualifying pair are unavailable and counted. If fewer than 90 percent of bootstrap replicates are valid, its interval is unavailable. Degenerate intervals in all-success/all-failure samples describe empirical resampling only and are not proof that population risk is zero. These intervals concern the frozen finite cohort and sampled seed family under this resampling model; they do not establish universal generalization.

Only the aggregate certification difference is the primary inferential comparison. Per-regime intervals and other methods are descriptive, without multiplicity-adjusted confirmatory claims. The earlier proposed 20 percent runtime reduction target can be discussed only as a conditional descriptive threshold; it is not a substitute for certification success.

## Completion curves and timing scope

For each method/regime within the preselected timing cohort, show the empirical fraction of eligible runs certified by time `t`, based on run-median total durations. Every eligible failure remains in the denominator at every time and never becomes a completion event. Unavailable methods have no execution-time curve; their counts remain visible. These are empirical observed completion fractions, not Kaplan-Meier survival estimates, censoring-adjusted probabilities, or interpolated within-run first-hit timings. Variants of each base are equally weighted; a learned-family curve would additionally average seeds, while published figures retain individual seed methods. Each panel explicitly states its small timing-cohort base count.

Total timing includes solve and post-solve verification, including learned inference performed inside solving. Report timing-cohort per-run median verification duration and verification/total fraction separately. Warmup is excluded from the five saved cohort timings. The noncohort single observations are explicitly labeled excluded from runtime analysis. Cold JVM startup is excluded and unmeasured. Reference construction, diagnostics, report I/O, visualization, training, and label generation are excluded from solve timings. Environment metadata and external-load limitations are copied from the manifest.

Training-cost break-even is unavailable by default. An optional, explicit cost JSON may supply `totalSeconds`, `complete: true`, and `timingComparable: true`, covering data/label generation, preprocessing, all retained model training and validation selection costs. Only when every primary pair in the preselected timing cohort is certified, no cohort timing is missing, the cost scope is complete/comparable, and mean paired solve-time savings are positive may the script report `ceil(totalSeconds/meanSavingsSeconds)` as an amortization scenario for repeated solves distributed exactly like that timing cohort. It is not a deployment or full-120-cohort forecast and is not calculated from a post-selected successful subset. Otherwise the report gives the reason it is unavailable. No training cost is inferred from numerical counters.

## Qualified reference checks and diagnostics

Parse exact decimal and rational strings without floating-point comparison. Only `ANALYTIC` and `VERIFIED_ENCLOSURE` references support a certificate-violation decision. A verified lower error endpoint strictly above its certificate is a violation; an upper endpoint above it is inconclusive. Preserve reference quality, lower and upper endpoints, reference error, and distance to the staircase separately. Any verified violation blocks a correctness claim and gives the CLI a nonzero exit status after writing the diagnostic report. Absence of violations on qualified scalar cases is not a continuous proof or joint 2D validation.

Alpha diagnostics retain `BOTH_EMPTY`, `REFERENCE_EMPTY`, and `APPROXIMATION_EMPTY` statuses with absent ordinary Hausdorff distances. Aggregate these as counts, not fabricated zeros. Do not interpret finite atom counts as topological components. Refinement histories remain preserved as input evidence and are never treated as independent samples.

## Deliverables and limits

Produce `analysis.json`, `report.md`, `method-regime-summary.csv`, `primary-effects.csv`, normalized per-run timing/verification summaries, and publication figures in PNG, SVG, and PDF: outcome heatmap, paired algorithm-work scatter, observed completion curves, qualified reference brackets versus certificates, and bootstrap effects when estimable (an explicit unavailable panel otherwise). All figures state relevant conditional or scalar scope. Save input and analysis file SHA-256 hashes and numerical-library versions. Existing raw evidence and model-seed rows remain authoritative and are not rewritten.

All outputs discuss finite cohort size, local uncontrolled timing conditions, scalar-only qualified continuous reference geometry, fixed numerical budgets, metric sensitivity to weak components, and unresolved closest-literature novelty comparison. No chart establishes a new theorem or efficiency advantage in advance. Final data are not generated, invented, or read while this plan and implementation are being frozen.

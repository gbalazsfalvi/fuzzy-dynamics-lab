# Milestone 04: isolated learned refinement

**Delivery date:** 17 November 2026.  
**Scope:** empirical ranking, train/validation labels, frozen models, and cross-runtime inference.  
**Numerical boundary:** model scores choose refinements; the existing directed decimal CAE engine computes bounds and verifies complete snapshots independently of those scores.

## What the model decides

The neural network predicts a signed local horizon-bound reduction for a candidate initial cell. Its nonnegative predicted reduction is divided by the declared child work estimate to rank active cells. Creation age resolves ties, and every fifth selection remains FIFO.

A score is not a membership value, trajectory radius, or certificate. Negative, unhelpful, or inaccurate predictions do not invalidate a complete numerical partition. They can make refinement inefficient.

Both child computations and both child score computations complete before any parent is removed. An arithmetic or missing-score failure leaves the last complete cover intact. The solver's best and last snapshots retain their original meanings.

## Data separation

The frozen split contains 208 distinct mathematical base problems. Its manifest tests check full mathematical-definition uniqueness and disjoint group identities:

| Partition | Base problems | Label rows |
| --- | ---: | ---: |
| Training | 64 | 6,208 |
| Validation | 24 | 2,328 |
| In distribution, scalar test | 30 | Not exported |
| In distribution, two dimensional test | 30 | Not exported |
| Out of distribution, scalar test | 30 | Not exported |
| Out of distribution, two dimensional test | 30 | Not exported |

All definitions are exact rational text. The split generator runs before collecting labels. The Java exporter skips every final test group; the Python loader rejects rows from forbidden groups or mixed partitions.

For training and validation, an ordinary maximum-bound exploration visits up to 97 complete cells per problem. Each is tentatively split into two complete verified children. The label is the original cell's worst horizon contribution minus the maximum child contribution, and can be negative. This is a local trial label, not an oracle for the resulting full partition's global improvement.

Actual trial work over 8,536 labels was 17,072 cell attempts, 107,088 map interval images, 53,544 spatial Lipschitz bounds, 34,144 membership ranges, and 17,072 membership Lipschitz queries. Exploration work is recorded separately per problem.

## Features and training

The fixed 16-feature recipe includes dimension, horizon, depth, initial radius, membership grade/error/variation/cap, horizon and next-step bounds, terminal and maximum/mean radii, maximum local Lipschitz bound, enclosure tightening, and cell shape. No test identity, trial child result, or reference discrepancy is a feature.

Feature means/scales and target normalization are fitted only on training rows. The models are:

- Ridge regression with alpha one, serving as the simple interpretable comparison.
- Five independently seeded networks, each with one 16-unit tanh hidden layer and a linear regression output. Seeds are 11, 23, 37, 51, and 71.

Each network uses the fixed L-BFGS budget of 1,200 iterations and regularization 0.01. All five reached that iteration cap, and their optimizer warnings are preserved. These are finite trained fits; convergence to an optimum is not claimed.

Validation label mean squared errors were approximately 0.002311 for ridge and 0.000778 to 0.000900 across the five networks. The zero-gain predictor had MSE about 0.006428. Better gain prediction does not establish a better refinement policy: that question belongs to the isolated solve-level validation and held out comparison.

No best-seed network is selected. If the MLP family is chosen on validation, all five seeds remain in its final evaluation.

## Frozen export and parity

Each JSON model contains explicit scaler values, layer weights and biases, activation declarations, feature recipe and order, seed, training CSV hash, and training code/dependency hash. The Java core uses no machine learning framework or third-party runtime dependency.

The parity fixture records predictions from the actual fitted Python estimators on training, validation, and controlled stress feature vectors. Java checked 576 predictions across all six models. The observed maximum absolute difference was about 5.35e-16, within the predeclared absolute/relative tolerance 1e-10.

This parity is about the exported heuristic function. It does not certify the quality of the model or replace mathematical bound verification.

~~~

Create the environment with Python 3.13 and use JDK 21 for Java tasks. The environment pins direct and transitive dependency versions and release file SHA-256 hashes. Training scripts fix numerical worker thread counts before importing BLAS-backed libraries. These commands create a new trained artifact; reuse the release's frozen models when replaying its exact numerical decisions. The full sequence through solve-level validation and final freeze is in [REPRODUCIBILITY.md](../REPRODUCIBILITY.md).

Frozen data and models are different artifacts. Generated label CSVs live in artifacts/learning/labels; the small inference models and parity cases live in learning/models. A release must identify the exact frozen weights rather than silently substitute a retrained fit.

## Evaluation handoff

The validation runner compares the four deterministic policies, ridge, all five networks, 20 seeded random-priority controls, and eligible scalar alpha/PWL baselines. Validation selection requires the complete paired cohort and a matching successful Java replay receipt.

The final protocol records the selected deterministic comparator and learned family before opening final outcomes. Its pre-run guard checks numerical source, protocol, model, and analysis provenance and requires a fresh output directory. The selected comparator/family must be identified by its verified selection artifact; the label-error figures above do not preselect a winning solve-level method.

The random-priority control uses reproducible per-path keys and the same fairness engine; it is not described as independent uniform selection among active leaves.

## Limits

These synthetic maps and feature distributions do not validate a physical application. Learned ranking may lose under shifted parameters, narrower peaks, longer horizons, or stronger deterministic baselines. Timing, success, label accuracy, and mathematical validity require separate evidence.

The closest literature full text comparison and external mathematical review remain open. No novelty or speedup claim follows from the training milestone.
